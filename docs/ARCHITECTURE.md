# Архитектура Family Tree

## Текущее состояние (0.2.0)

Приложение ещё использует один Android-модуль и исходные Activity/Fragment.
Новый слой хранения изолирует основную запись и загрузку семей от экрана и
сериализации:

```text
Activity / Fragment ───────┐
                          TreeUtil (compatibility facade)
                            │
                            ▼
                      TreeRepository
                            │
                            ▼
                   FileTreeRepository
                            │
                      <tree-id>.json
```

- `TreeRepository` — интерфейс асинхронного чтения/записи GEDCOM-модели.
- `FileTreeRepository` — реализация для внутренних файлов Android.
- `LegacyTreeJson` — поддержка прежних JSON-ключей `zona`, `famili`,
  `passato`; не преобразует пользовательские значения.
- `TreeUtil` — пока служит совместимым фасадом для Java/Kotlin-экранов.
  В нём остаются уведомления о днях рождения и резервное копирование.
- `AppCoroutineScope` — явный scope жизненного цикла процесса для операций,
  которые нельзя прерывать при повороте экрана. UI использует `lifecycleScope`.

## Инварианты совместимости

1. **Формат не изменён**: каждое дерево хранится в `filesDir/<id>.json`,
   совместимом с исходным `org.folg.gedcom.parser.JsonParser`.
2. **Запись без усечения старого файла**: JSON сначала полностью записывается
   во временный файл в той же директории, синхронизируется на диск, затем
   заменяет прежний файл через `renameTo`. При ошибке временный файл удаляется.
3. **Старые деревья читаются без миграции базы**. Импорт/экспорт GEDCOM,
   медиа и ZIP сохраняют существующее поведение.
4. **Уведомления и резервное копирование** запускаются после успешной записи;
   ошибка сохранения не должна вызывать резервную копию несохранённых данных.

## Технический долг

- `Global.gc`, `Global.settings` и прочее общее изменяемое состояние
  ещё используется большинством экранов. Изолировать постепенно.
- Новый фасад используется для основного `TreeUtil`. Некоторые операции
  создания, восстановления ZIP и сторонние методы продолжают писать файлы
  напрямую; переносить их после добавления тестов на конкретные сценарии.
- Отдельный сервис Family Tree для онлайн-обмена не создан. Оставшиеся
  интеграции с `familygem.app` нельзя считать независимыми.
- Следующим этапом выделить модели UI, ViewModel/StateFlow и постепенно
  перевести экраны на Compose + Material 3. Движок GEDCOM-графа пока сохраняем.

## Проверка

На `nadein-core`:

```bash
cd ~/Dev/family-tree-android
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

Новые тесты покрывают UTF-8, несколько деревьев, повторную запись,
совместимость JSON, обработку неудачного сохранения, старые ключи,
некорректный JSON и GEDCOM round-trip. Рекомендуется также проверка
на физическом Android-устройстве перед выпуском релизного APK.
