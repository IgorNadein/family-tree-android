# Архитектура Family Tree

## Текущее состояние (0.2.0)

Приложение ещё использует один Android-модуль и исходные Activity/Fragment.
Новый слой хранения изолирует основную запись и загрузку семей от экрана и
сериализации:

```text
Activity / Fragment ───────┐
                          TreeUtil (compatibility facade)
                            │
                            ▼
                      TreeRepository
                            │
                            ▼
                   FileTreeRepository
                            │
                      <tree-id>.json
```

- `TreeRepository` — интерфейс асинхронного чтения/записи GEDCOM-модели.
- `FileTreeRepository` — реализация для внутренних файлов Android.
- `LegacyTreeJson` — поддержка прежних JSON-ключей `zona`, `famili`,
  `passato`; не преобразует пользовательские значения.
- `TreeUtil` — пока служит совместимым фасадом для Java/Kotlin-экранов.
  В нём остаются уведомления о днях рождения и резервное копирование.
- `AppCoroutineScope` — явный scope жизненного цикла процесса для операций,
  которые нельзя прерывать при повороте экрана. UI использует `lifecycleScope`.

## Инварианты совместимости

1. **Формат не изменён**: каждое дерево хранится в `filesDir/<id>.json`,
   совместимом с исходным `org.folg.gedcom.parser.JsonParser`.
2. **Запись без усечения старого файла**: JSON сначала полностью записывается
   во временный файл в той же директории, синхронизируется на диск, затем
   заменяет прежний файл через `renameTo`. При ошибке временный файл удаляется.
3. **Старые деревья читаются без миграции базы**. Импорт/экспорт GEDCOM,
   медиа и ZIP сохраняют существующее поведение.
4. **Уведомления и резервное копирование** запускаются после успешной записи;
   ошибка сохранения не должна вызывать резервную копию несохранённых данных.

## 0.2.1: стабилизация интерфейсной архитектуры

Версия 0.3.0 привела к блокировке касаний: `ComposeView` перехватывал
клики, а `TreesActivity` продолжал ждать события старого `View`.
Горячая правка 0.3.1 не устранила саму зависимость UI от `performClick()`.

Поэтому ветка `master` вернулась к XML-интерфейсу 0.2.0. Все изменения
Compose сохранены в `experiment/compose-0.3.1` для последующей переработки.
Новая базовая версия `0.2.1` имеет `versionCode=6`, чтобы обновляться
поверх 0.3.1 без удаления данных. Формат `<id>.json` не изменился.

### Граница экран / сценарий / хранилище

```text
TreesActivity (Android Views)
    ├── TreeListViewModel [StateFlow<List<TreeListItem>>]
    ├── TreeSelectionPolicy / TreeMenuPolicy
    ├── OpenTreeUseCase [открытие без повторной загрузки]
    └── TreeListGateway (interface)
           └── LegacyTreeListGateway [Global/TreeUtil adapter]
```

- ViewModel хранит **неизменяемые снимки**, не объекты `Settings.Tree` или
  `Gedcom`; UI больше не решает тип действия по условным блокам.
- `OpenTreeUseCase` возвращает результат, но не вызывает `startActivity`.
  Навигация остаётся у Activity, на главном потоке.
- `TreeMenuPolicy` описывает меню без зависимости от Android.
- `TreeListViewModel.beginOpening()/finishOpening()` защищают от двух
  одновременных переходов.
- `LegacyTreeListGateway` — временный адаптер `Global`. Удалять его
  только после полной миграции хранения настроек и GEDCOM.
- Unit-тесты проверяют состояния 0/10/20/30, меню, переходы,
  повторные касания и отрицательные результаты загрузки.
- `TreesActivityTouchTest` проверяет реальное касание названия и Intent
  перехода (для уже загруженного и холодного дерева), доступность меню
  дерева и создание новой семьи через Android UI.
  Выполнять только на изолированном эмуляторе: тест создаёт временные файлы
  и настройки, после тестов возвращает исходное состояние приложения.

### Обязательные критерии перед новым Compose-экраном

1. **Зелёные unit + Android UI-тесты**. Тест именно видимого касания,
   не только вызова `performClick()`.
2. Регрессионные сценарии: создание, редактирование, удаление, импорт,
   экспорт GEDCOM/ZIP, перетаскивание и открытие дерева после перезапуска.
3. У новой Compose-карточки — прямой вызов действия (например,
   `onTreeSelected(id)`), без пересылки события Android Views.
4. Стабильное состояние списка и сохранность всех `<id>.json`.
5. Отдельная проверка на Android-устройстве и возможность возврата к
   0.2.x без удаления данных.

**Эти критерии ещё не все закрыты**. Другие экраны используют `Global`;
вспомогательные пути импорта и ZIP не вынесены в репозиторий;
зависимости от `familygem.app` остаются. Нельзя считать архитектуру
всего приложения полностью очищенной.

## Технический долг

- `Global.gc`, `Global.settings` и прочее общее изменяемое состояние
  ещё используется большинством экранов. Изолировать постепенно.
- Новый фасад используется для основного `TreeUtil`. Некоторые операции
  создания, восстановления ZIP и сторонние методы продолжают писать файлы
  напрямую; переносить их после добавления тестов на конкретные сценарии.
- Отдельный сервис Family Tree для онлайн-обмена не создан. Оставшиеся
  интеграции с `familygem.app` нельзя считать независимыми.
- Следующим этапом выделить модели UI, ViewModel/StateFlow и постепенно
  перевести экраны на Compose + Material 3. Движок GEDCOM-графа пока сохраняем.

## Проверка

На `nadein-core`:

```bash
cd ~/Dev/family-tree-android
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

Новые тесты покрывают UTF-8, несколько деревьев, повторную запись,
совместимость JSON, обработку неудачного сохранения, старые ключи,
некорректный JSON и GEDCOM round-trip. Рекомендуется также проверка
на физическом Android-устройстве перед выпуском релизного APK.
