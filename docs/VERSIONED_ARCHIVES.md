# .ftree: обмен семейными деревьями с историей

## Версия 2 (Family Tree 0.2.4)

`.ftree` — независимый от сервера ZIP-архив с Git-подобной историей,
снимками GEDCOM и адресуемыми по SHA-256 вложениями. Это **не** репозиторий
Git и не протокол GitHub: обмен происходит вручную через файлы.

### Пользовательский сценарий

1. Меню дерева → «Экспорт с историей (.ftree)». В архив попадут все ревизии
   и доступные локальные фотографии, видео, PDF и любые другие файлы,
   на которые ссылаются GEDCOM-медиа. Нечитаемые локальные вложения
   блокируют экспорт с ошибкой: нельзя молча выдавать неполный архив.
   Интернет-ссылки не скачиваются, они остаются ссылками.
2. Передайте файл доверенному родственнику. Он импортирует его через
   «Добавить дерево» → «Импорт с историей (.ftree)».
3. После независимых правок родственник экспортирует новую копию `.ftree`.
4. Меню исходного дерева → «Объединить из .ftree»: трёхстороннее слияние
   по общему предку. Совпадающие правки автоматически объединяются, а
   конфликты данных или содержимого файлов выбираются вручную.
5. Результат слияния образует новый коммит с двумя родителями.

### Содержимое

~~~
family.ftree (ZIP)
├── manifest.json              # version=2, tree UUID, head hash
├── title.json
├── commits/
│   └── <sha256>.json          # DAG, GEDCOM JSON, media: {reference: blob-hash}
└── blobs/
    └── <sha256>               # исходные байты любого локального вложения
~~~

- Один бинарный объект хранится **один раз** независимо от количества
  ссылок или ревизий. Различные файлы с одинаковыми именами сохраняются
  раздельно (индексируется полная GEDCOM-ссылка, а не basename).
- Замена файла с тем же именем порождает новый коммит даже при
  неизменённом GEDCOM JSON; старые версии содержимого сохраняются.
- Хеш коммита v2 покрывает также карту вложений. Старые v1-коммиты
  сохраняют исходную формулу SHA-256 и идентификаторы.
- Содержимое передаётся и проверяется **потоково** блоками по 64 КиБ,
  не загружая фото или видео целиком в оперативную память.
- При импорте бинарные объекты сохраняются в
  `filesDir/.ftree-history/<id>/blobs/<hash>`, а для отображения создаются
  отдельные рабочие копии в `getExternalFilesDir(<id>)/.ftree-files`.
  Исходные `OBJE.FILE` и хеши коммитов не переписываются;
  `FileUri` разрешает оригинальную ссылку через карту `working-media.json`.
- Для избежания повторного хеширования гигабайтных файлов при каждом
  сохранении используется кеш размера/mtime/пути источника.
  При **экспорте** содержимое всегда проверяется заново.
- Искусственные ограничения v1 (64 МиБ суммарно, 16 МиБ на запись,
  1024 коммита) для v2 удалены. Размер ограничивается доступным
  местом на диске, возможностями файловой системы/ZIP и памятью,
  требуемой для обработки *JSON-истории*, но не размером отдельного видео.
  Тестом проверен потоковый round-trip файла 70 МиБ.

### Совместимость v1

Приложение читает старые `.ftree v1` без вложений. При следующем
сохранении/экспорте появляется ревизия v2, фиксирующая **доступные сейчас**
вложения. Восстановить старые версии файлов, которые никогда не
содержались в v1, невозможно. Старые приложения 0.2.3 не читают v2.

### Конфликты и безопасность

- JSON сливается по отдельным верхнеуровневым GEDCOM-записям, вложения —
  по пути ссылки и SHA-256 содержимого. При разных правках одной записи
  или разных версиях файла требуется выбор пользователя.
- Все файлы ZIP разрешаются по строгому списку путей, хеши проверяются,
  дубликаты путей отвергаются. Неизвестные версии и оборванная история
  блокируются до импорта.
- Нет криптографической подписи автора и нет шифрования. Поскольку история
  содержит все прошлые снимки и бинарные объекты, **удаление человека
  или фото из текущего дерева не удаляет их из истории**. Передавайте
  файлы только доверенным людям.
- Не все возможности Git уже реализованы: нет удалённых репозиториев,
  веток с именами, просмотра отличий полей, автоматической синхронизации
  и UI-отката. Масштабирование миллионов JSON-коммитов пока ограничено
  тем, что индексы коммитов при слиянии загружаются в память.
- Уровень истории v2 не заменяет независимую зашифрованную резервную копию.

### Проверка

`VersionedTreeArchiveTest`: слияние, общие предки, конфликты,
совместимость коммитов и защита от подмены.

`VersionedMediaArchiveTest`: одинаковые имена, смена байтов без правок
JSON, конфликт двоичных версий, проверка SHA-256, круговой перенос
вложения размером 70 МиБ и импорт старого v1.

`FileTreeRepositoryTest`: накопление истории после обычного сохранения.

Обязательно выполнить ручную проверку SAF-импорта и экспорта на Android,
включая фотографии с SD-карты или внешней папки.
